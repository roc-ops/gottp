# Fix multi-template child element loss

## What
Child `<group>` elements are discarded in multi-template documents. When a document contains multiple `<template>` sections, child group elements within them are lost during parsing.

## Detailed Requirements
- Investigate how multi-template documents parse child `<group>` elements
- Fix so that child groups are preserved across all templates in a multi-template document
- This is a real defect reported from an application using the library

## Exploration

- Bug was NOT resolved by REQ-002 (different code path - multi-template vs nested groups)
- Two bugs found:
  1. Parser `ParseTemplate` overwrote `root` on each iteration, keeping only last template
  2. `parseChildTemplate` dropped child XML elements (had a `_ = child` and TODO comment)

*Generated by implementation agent exploration*

## Implementation Summary

- Fixed `internal/parser/template.go` ParseTemplate: wraps in synthetic `<_root_>` to collect all templates
- Fixed `internal/parser/template.go` parseChildTemplate: constructs Template from parsed xmlElement directly (replaces broken re-serialization)
- Fixed `internal/compiler/compiled.go`: hoists groups/elements from child templates into root compiled template
- Created `test/multi_template_test.go` with 3 regression tests
