# Fix inner group output mismatch with Python TTP

## What
gottp produces different results than Python TTP when a template uses an unnamed inner `<group>` inside a named outer group with `method="table"`. Removing the inner group makes gottp match Python output. With the inner group present, gottp does not match Python TTP's output.

## Detailed Requirements
- Diagnose why the inner group inside `<group name="yang.if-mib:IF-MIB.ifTable.ifEntry*" method="table">` causes different output in gottp vs Python TTP
- The inner `<group>` (unnamed) wraps all the match lines and the outer group has `_start_` on `ifIndex`
- Without the inner group, gottp matches Python — so the issue is specifically in how gottp handles unnamed inner groups within named table-method groups
- Fix the behavior so gottp matches Python TTP output
- Add a test case using the provided template to confirm the fix and prevent regression

## Context
User provided a full template with:
- `<macro>` section (Python-specific, gottp ignores)
- `<lookup name="ifTypes">` for rlookup
- Outer group: `<group name="yang.if-mib:IF-MIB.ifTable.ifEntry*" method="table">`
- Inner group: unnamed `<group>` containing all match patterns
- `_start_` indicator on `ifIndex` line
- Multiple match patterns with functions: `DIGIT`, `to_int`, `ORPHRASE`, `lower`, `rlookup`, `ignore`

## Exploration

- **Root cause:** In `internal/compiled/runtime.go` line 3249, the condition `nestedGroup.Name == "_"` only handles underscore-named groups for merging into parent match. Unnamed groups (`Name == ""`) fall through to the `else` block which tries to resolve an empty path via `storeAtPath`, creating incorrect output structure.
- Line 4519 in `parseGroupWithSourceMap` already correctly checks `nestedGroup.Name == "" || nestedGroup.Name == "_"` — the fix at line 3249 should match this pattern.
- With `method="table"`, all patterns become start patterns. The unnamed inner group's results should transparently merge into the parent match like `"_"` groups do.
- Relevant test files: `test/nested_groups_test.go`, `test/method_attribute_test.go`, `test/comparison/groups_attributes_test.go`

## Implementation Summary

- Fixed `internal/compiled/runtime.go` line 3249: added `|| nestedGroup.Name == ""` to merge condition so unnamed groups merge into parent like `"_"` groups
- Fixed `parseGroup` early return (line ~1023): when outer group has no patterns but has unnamed nested groups, delegate to inner group instead of returning nil
- Applied same early return fix to `parseGroupWithSourceMap` (line ~4055) for consistency
- Created `test/unnamed_inner_group_test.go` with two test functions
